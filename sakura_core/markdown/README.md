# Markdown プレビュー

エディタの右側に Markdown のプレビューを表示する機能です。Win32/GDI で描画します(WebView2 は使いません)。

## 構成

| ファイル | 役割 | 依存 |
|---|---|---|
| `MarkdownModel.h` | 中間データモデル(ブロックとインライン要素) | 標準ライブラリのみ |
| `IMarkdownParser.h` | パーサーのインターフェース | モデル |
| `Md4cParser.{h,cpp}` | md4c を使ったパーサー。md4c を取り込むのはこのファイルだけ | md4c |
| `MarkdownText.h` | UTF-16 の文字判定(東アジアの文字、禁則処理) | 標準ライブラリのみ |
| `MarkdownLayout.{h,cpp}` | 折り返しと配置。文字の幅は `ITextMeasurer` から取る | モデル |
| `CMarkdownPreviewWnd.{h,cpp}` | 子ウィンドウ。レイアウトの結果を GDI で描き、スクロールを処理する | Win32 |
| `MarkdownHeadingScanner.{h,cpp}` | 1行ずつ受け取り、見出しを見つける(アウトライン解析用) | 標準ライブラリのみ |
| `MarkdownHtml.{h,cpp}` | 文書を、クリップボード用の HTML(CF_HTML)とプレーンテキストにする | モデル |

エディタ本体との接点は `CEditWnd`(`ToggleMarkdownPreview` など)だけです。
パーサーは `IMarkdownParser` を介して使うので、別のパーサーに交換するときは、
`MarkdownModel.h` のモデルを作る実装を用意すれば、描画側は変更不要です。

## コピー

プレビューを右クリックすると、メニューからコピーできます。プレビューにフォーカスがあるときは、キーでもコピーできます。

| メニュー | キー | クリップボードに入るもの |
|---|---|---|
| 書式付きでコピー | Ctrl+C | `HTML Format`(CF_HTML)と `CF_UNICODETEXT` |
| 画像としてコピー | Ctrl+Shift+C | `PNG` と `CF_DIB`(プレビューと同じ見た目) |

- 書式付きのコピーは、Teams、Outlook、Word などに貼ると、表・見出し・リスト・コードブロックが書式付きで貼られます。
  貼り付け先は `<style>` を捨てることが多いので、書式はすべて要素の `style` 属性に書きます(`MarkdownHtml.cpp`)。
  - 画像は、プレビューに表示できているものだけを `data:` URI で埋め込みます(合計 32MiB まで)。それ以外は `[代替テキスト]` です。
  - リンクは `http:`、`https:`、`mailto:` のものだけをリンクにします。
  - プレーンテキストでは、表の列をタブで区切ります(Excel に貼れます)。
  - 貼り付け先ごとの癖に合わせています。Word は `<del>` の文字を変更履歴の削除として隠すので、取り消し線は `<s>` にします。
    Word は `<hN>` の `font-size` を使わないので、見出しの中の `<span>` にも大きさを書きます。
    Teams は `<li>` の中の `<p>` の前で改行するので、リスト項目の最初の段落は `<p>` で囲みません(タスクのチェックと本文を同じ行にするため)。
  - Word の貼り付けの既定が「書式を結合」のときは、太字や斜体以外の書式(大きさ、フォント、背景)が落ちます。「元の書式を保持」で貼ってください。
  - モデルは入れ子を深さの数値で持つので、引用の中のリストは組み立てられますが、リストの中の引用は、引用の外側にリストがある形になります。
- 画像としてのコピーは、プレビューの幅で、文書全体を描きます。高さは 30000px までで、それを超える部分は切り捨てます。
- エディタのメッセージループは、キーを `TranslateAccelerator` でフォーカスのあるウィンドウへの `WM_COMMAND` に変えるので、
  プレビューは `WM_COMMAND` でキーを受け取ります(`CMarkdownPreviewWnd::OnAccelerator`)。コピーとスクロール以外のキーは無視します。

## 印刷

プレビューの右クリックメニューの「プレビューを印刷」、またはプレビューにフォーカスがあるときの Ctrl+P で、
プレビューの内容を印刷します(エディタの「ファイル」→「印刷」は、これまでどおり Markdown のテキストを印刷します)。

- プリンターの解像度でレイアウトし直します(`CMarkdownPreviewWnd::Print`)。文字は画面と同じポイント数です。
- 画面の配色によらず、白地に黒で印刷します。余白は 15mm で、下の余白にページ番号(`1 / 5`)を入れます。
- ページ分けは `PaginateLayout`(`MarkdownLayout.cpp`)です。文字の行、画像、塗りつぶし(表の罫線、コードの背景、引用の縦線)のうち、
  1ページに収まるものはページの境目で切らずに、次のページに送ります。1ページより高いものは切ります。
- プリンターでは、次の2点を画面と変えています。
  - 画像は `AlphaBlend` を使わず、白地に合成してから `StretchDIBits` で描きます(`AlphaBlend` に対応しないドライバーがあるため)。
  - 塗りつぶしは `DC_BRUSH` を使わず、色ごとにブラシを作ります(スプールの EMF では `SetDCBrushColor` の色が効かないため)。
- 選んだプリンターと設定は、エディタを閉じるまで覚えています。PDF にしたいときは「Microsoft Print to PDF」を選んでください。
- 印刷プレビューの画面はありません。

## 色分けとアウトライン

タイプ別設定「Markdown」(`types/CType_Markdown.cpp`)で、編集画面に色を付けます。拡張子は md、markdown、mdown、mkd です。
配色は GitHub の画面を参考にしています。

| ファイル | 役割 |
|---|---|
| `types/CType_Markdown.cpp` | タイプ別設定の既定値(正規表現キーワード、配色)、古い版の設定の移行、アウトライン解析 |
| `view/colors/CColor_MarkdownFence.{h,cpp}` | フェンスで囲んだコードブロックの色分け(行をまたぐ範囲として扱う) |
| `MarkdownCodeTokenizer.{h,cpp}` | コードブロックの1行を、言語ごとの規則で字句に分ける(標準ライブラリのみ) |

- 見出し、太字、斜体、取り消し線、インラインコード、リンク、引用、リストの記号、区切り線、表、HTML には、
  正規表現キーワード1～10で色を付けます。
- フェンスで囲んだコードブロック(```` ``` ```` と `~~~`)は、全体を「コメント」の色にし、その中の字句に
  ```` ```bash ```` などの言語に合わせて「強調キーワード1～10」の色を付けます。
  1: キーワード、2: 文字列、3: コメント、4: 数値と定数、5: 変数とキー、6: 関数名とコマンド名、
  7: タグ、8: 属性名、9: 差分の追加行、10: 差分の削除行 です。
  対応する言語は `GetCodeLanguage` を見てください。言語の指定がないときは、文字列、数値、コメントだけに色を付けます。
  - 描画の途中で色を変えるため、`CColorStrategy` に `GetDrawColor` と `UpdateDrawColor` を加えています。
    範囲の識別(レイアウトに記録する色)は `COLORIDX_MARKDOWN_FENCE` のままで、描画の色だけを字句ごとに変えます。
  - タイプ別設定の `m_bMarkdownCodeBlock`(INI では `bMarkdownCodeBlock`)で有効にします。
  - 字句は1行ずつ調べるので、行をまたぐ文字列やコメントは、その行の分だけに色が付きます。
    印刷とクリップボードへの色付きのコピーでは、コードブロック全体が「コメント」の色になります。
- アウトライン解析(`OUTLINE_MARKDOWN`)は、見出しのレベルで階層にします。
  コードブロック、先頭の YAML front matter、HTML のコメントの中は見出しにしません。
- 正規表現キーワードは1行ずつ調べるので、行をまたぐ強調には色が付きません。
  また、プレビュー(md4c)と違って CommonMark の規則を簡略化しているため、細かいところで結果が異なることがあります。

### 古い設定の移行

- Markdown のタイプ別設定がない INI を読むと、一度だけ末尾に追加します(`[Other]` の `bMarkdownTypeAdded`)。
- 既定の配色などを変えたときは `MARKDOWN_TYPE_VERSION` を上げ、`UpgradeMarkdownTypeConfig` に移行を書きます。
  INI の `[Other]` の `nMarkdownTypeVersion` が古いと、前の版の既定値のままの色だけを今の版の色にします(利用者が変えた色は残します)。

## md4c

- https://github.com/mity/md4c (MIT License, Copyright (c) 2016-2026 Martin Mitáš)
- vcpkg のローカルレジストリ(`tools/vcpkg-local-registry/ports/md4c`)で、UTF-16 版(`MD4C_USE_UTF16`)をビルドします。
  この定義は `md4c.h` の `MD_CHAR` の型を変えるので、`md4c.h` を取り込む側も同じ定義が要ります(`Md4cParser.cpp` が定義します)。
- 生 HTML は解釈せず、文字列として表示します(`MD_FLAG_NOHTMLBLOCKS` と `MD_FLAG_NOHTMLSPANS`)。
- ポートには、md4c 0.6.0 に対するパッチ(`strikethrough-flanking.patch`、`md4c.c` の約 20 行)を当てています。
  取り消し線(`~~`)の開始・終了の判定を、`*` の強調と同じ規則(前後が空白か句読点か、それ以外の文字か)にするものです。
  そのままの md4c 0.6.0 は、`~~` を語中の `_` と同じ扱いにするので、`日本語~~取消~~です` や `ASCII~~del~~text` のように
  前後が文字だと取り消し線になりません。GitHub の参照実装(cmark-gfm)はどちらも取り消し線にします。
  - 確認: 同じ入力を cmark-gfm に通した結果と比べました。`~` だけを含むランダムな 40000 行で、食い違いは 380 行から 22 行に減りました。
    残りはすべて、同じ行に `~` と `~~` が混在するものです。
  - md4c を更新するときは、パッチが当たるかと、`test-md4cparser.cpp` の `InlineDelimitersInJapanese` が通るかを確認してください。
    上流が同じ修正を取り込んだら、パッチは不要になります。

## 既知の制限

- 強調の規則は CommonMark と同じです(GitHub の参照実装 cmark-gfm でも同じ結果になることを確認しています)。
  日本語の文章では、次の点に注意してください。
  - `_` は語中では強調になりません。`日本語_強調_です` は、そのまま表示されます。`日本語 _強調_ です` なら強調です。日本語には、前後が文字でも使える `*` を使ってください(`日本語*強調*です`)。
  - 内側の端が句読点や括弧で、外側が文字のときは、`*` も `~~` も効きません。`**「強調」**です`、`**強調。**次の文`、`~~「取消」~~です` は、そのまま表示されます。
    `**「強調」** です` のように、外側に空白を置くと強調になります。これは CommonMark の既知の制約で、md4c 固有の問題ではありません。
  - 同じ行に `~` と `~~` が混在するときは、cmark-gfm と結果が異なる場合があります。
- 画像はローカルのファイルだけです。文書のあるフォルダの中にあるものを、読み込めたときに表示します。
  それ以外(URL、絶対パス、`..` で外に出るもの、リンクで外を指すもの、保存前の文書)と、読み込めなかったものは、`[代替テキスト]` の形で表示します。
- リンクは表示するだけで、クリックしても開きません。
- 編集には、約 1 秒の遅れで追従します(`CEditWnd::UpdateMarkdownPreviewIfNeeded`)。解析は別のスレッドで行います。
- 解析する上限は 2Mi 文字(UTF-16 のコードユニット)、ブロック数は 10 万です(`ParseOptions`)。
