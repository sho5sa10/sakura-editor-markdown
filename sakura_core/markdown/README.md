# Markdown プレビュー

エディタの右側に Markdown のプレビューを表示する機能です。Win32/GDI で描画します(WebView2 は使いません)。

## 構成

| ファイル | 役割 | 依存 |
|---|---|---|
| `MarkdownModel.h` | 中間データモデル(ブロックとインライン要素) | 標準ライブラリのみ |
| `IMarkdownParser.h` | パーサーのインターフェース | モデル |
| `Md4cParser.{h,cpp}` | md4c を使ったパーサー。md4c を取り込むのはこのファイルだけ | md4c |
| `MarkdownText.h` | UTF-16 の文字判定(東アジアの文字、禁則処理) | 標準ライブラリのみ |
| `MarkdownLayout.{h,cpp}` | 折り返しと配置。文字の幅は `ITextMeasurer` から取る | モデル |
| `CMarkdownPreviewWnd.{h,cpp}` | 子ウィンドウ。レイアウトの結果を GDI で描き、スクロールを処理する | Win32 |
| `MarkdownHeadingScanner.{h,cpp}` | 1行ずつ受け取り、見出しを見つける(アウトライン解析用) | 標準ライブラリのみ |

エディタ本体との接点は `CEditWnd`(`ToggleMarkdownPreview` など)だけです。

## 色分けとアウトライン

タイプ別設定「Markdown」(`types/CType_Markdown.cpp`)で、編集画面に色を付けます。拡張子は md、markdown、mdown、mkd です。

- 見出し、太字、斜体、取り消し線、インラインコード、リンク、引用、リストの記号、区切り線、表、HTML に、
  正規表現キーワード1～10で色を付けます。配色は VS Code の Light+ テーマを参考にしています。
- フェンスで囲んだコードブロック(```` ``` ```` と `~~~`)は、ブロックコメントとして色を付けます(色は「コメント」)。
- アウトライン解析(`OUTLINE_MARKDOWN`)は、見出しのレベルで階層にします。
  コードブロック、先頭の YAML front matter、HTML のコメントの中は見出しにしません。
- 正規表現キーワードは1行ずつ調べるので、行をまたぐ強調には色が付きません。
  また、プレビュー(md4c)と違って CommonMark の規則を簡略化しているため、細かいところで結果が異なることがあります。
パーサーは `IMarkdownParser` を介して使うので、別のパーサーに交換するときは、
`MarkdownModel.h` のモデルを作る実装を用意すれば、描画側は変更不要です。

## md4c

- https://github.com/mity/md4c (MIT License, Copyright (c) 2016-2026 Martin Mitáš)
- vcpkg のローカルレジストリ(`tools/vcpkg-local-registry/ports/md4c`)で、UTF-16 版(`MD4C_USE_UTF16`)をビルドします。
  この定義は `md4c.h` の `MD_CHAR` の型を変えるので、`md4c.h` を取り込む側も同じ定義が要ります(`Md4cParser.cpp` が定義します)。
- 生 HTML は解釈せず、文字列として表示します(`MD_FLAG_NOHTMLBLOCKS` と `MD_FLAG_NOHTMLSPANS`)。
- ポートには、md4c 0.6.0 に対するパッチ(`strikethrough-flanking.patch`、`md4c.c` の約 20 行)を当てています。
  取り消し線(`~~`)の開始・終了の判定を、`*` の強調と同じ規則(前後が空白か句読点か、それ以外の文字か)にするものです。
  そのままの md4c 0.6.0 は、`~~` を語中の `_` と同じ扱いにするので、`日本語~~取消~~です` や `ASCII~~del~~text` のように
  前後が文字だと取り消し線になりません。GitHub の参照実装(cmark-gfm)はどちらも取り消し線にします。
  - 確認: 同じ入力を cmark-gfm に通した結果と比べました。`~` だけを含むランダムな 40000 行で、食い違いは 380 行から 22 行に減りました。
    残りはすべて、同じ行に `~` と `~~` が混在するものです。
  - md4c を更新するときは、パッチが当たるかと、`test-md4cparser.cpp` の `InlineDelimitersInJapanese` が通るかを確認してください。
    上流が同じ修正を取り込んだら、パッチは不要になります。

## 既知の制限

- 強調の規則は CommonMark と同じです(GitHub の参照実装 cmark-gfm でも同じ結果になることを確認しています)。
  日本語の文章では、次の点に注意してください。
  - `_` は語中では強調になりません。`日本語_強調_です` は、そのまま表示されます。`日本語 _強調_ です` なら強調です。日本語には、前後が文字でも使える `*` を使ってください(`日本語*強調*です`)。
  - 内側の端が句読点や括弧で、外側が文字のときは、`*` も `~~` も効きません。`**「強調」**です`、`**強調。**次の文`、`~~「取消」~~です` は、そのまま表示されます。
    `**「強調」** です` のように、外側に空白を置くと強調になります。これは CommonMark の既知の制約で、md4c 固有の問題ではありません。
  - 同じ行に `~` と `~~` が混在するときは、cmark-gfm と結果が異なる場合があります。
- 画像はローカルのファイルだけです。文書のあるフォルダの中にあるものを、読み込めたときに表示します。
  それ以外(URL、絶対パス、`..` で外に出るもの、リンクで外を指すもの、保存前の文書)と、読み込めなかったものは、`[代替テキスト]` の形で表示します。
- リンクは表示するだけで、クリックしても開きません。
- 編集には、約 1 秒の遅れで追従します(`CEditWnd::UpdateMarkdownPreviewIfNeeded`)。解析は別のスレッドで行います。
- 解析する上限は 2Mi 文字(UTF-16 のコードユニット)、ブロック数は 10 万です(`ParseOptions`)。
